# v0.1.1

Everything here comes from one failure that took hours to diagnose by hand: a credential with the Drive scope, on an account that could open the Sheet, still returned 403 from the Drive API. The scope list was right. The account was right. The cause was an OAuth client difference nothing in the tooling surfaced.

## Two OAuth clients

`gcloud auth login` and `gcloud auth application-default login` use different OAuth clients. The resulting credential files differ in one opaque numeric id and nothing else, yet the client decides whether a Workspace tenant will show a Drive consent screen at all, and whether Google demands a quota project on every non-Cloud API call.

- `login --sdk-client` and `rescope --sdk-client` mint through `gcloud auth login` instead. Fixed scope set, because that command has no `--scopes` flag, but a consent screen that is usually still permitted.
- When a mint asks for Drive and Google grants everything except Drive, that is the signature of a tenant-side block rather than a wrong scope name. gcpx says so and offers to retry through the SDK client.

## Quota project

Auth-library credentials are refused by Drive and Sheets until they name a project to bill calls against. The 403 reads like a permissions problem, which is what makes it expensive.

- `login` and `adopt` now stamp the quota project automatically when the credential needs one.
- `gcpx set <alias> --quota-project auto` repairs an existing identity. No re-consent.

## New verb: set

```
gcpx set <alias>                                    show current defaults
gcpx set <alias> --project P                        default project
gcpx set <alias> --quota-project P|auto|none        quota project
gcpx set <alias> --description D --tags T --note N
```

Editing a default project previously meant re-minting, which threw away a working grant to change a string. It also meant an interrupted onboarding could silently leave an identity with no default project at all.

## Diagnostics

`doctor` now reports, per identity: which OAuth client minted it, what quota project is attached, and a live Drive call whose failure is attributed to a named layer rather than left as a status code.

```
    client   auth-library
    quota    NOT SET - Drive and Sheets will refuse this credential. Fix: gcpx set work --quota-project auto
    drive    quota-project layer: this account may not bill against the project currently set as quota
             project. No local fix -- it needs roles/serviceusage.serviceUsageConsumer there.
```

The layers are independent and all three deny with the same status code: the OAuth scope on the token, the quota project billed for the call, and Drive's own file sharing. `exec` warns up front when a drive-scoped credential has no quota project, since that combination cannot work.
