# v0.1.0

First release. Per-command Google Cloud identity selection, in the shape
`aws-vault` and `kubie` established and GCP never got.

## Running things

- `gcpx exec <alias> -- <cmd...>` builds a credential environment and replaces
  the process with the target command, so exit codes, signals and terminal
  control pass through untouched. Nothing is globally activated; concurrent
  invocations on different identities cannot interfere.
- Both `CLOUDSDK_AUTH_CREDENTIAL_FILE_OVERRIDE` and
  `GOOGLE_APPLICATION_CREDENTIALS` are set, because gcloud reads the first and
  ignores the second while the client libraries do the reverse. Setting one
  produces a setup that works in half the tools.
- Each identity gets its own `CLOUDSDK_CONFIG` directory, which keeps gcloud's
  shared access-token cache from becoming a contention point under
  concurrency. `--no-isolate` opts out.
- `gcpx env <alias>` prints the variables instead of running anything, for
  direnv, `EnvironmentFile=`, or an MCP server definition.

## Knowing what you have

- `gcpx ls` renders alias, email, project, scopes, state and — in every row —
  the literal command that fixes it. States are ASCII, output is greppable, and
  `--json` carries the full metadata including tags and known projects.
- Exit codes encode the verdict: `0` ok, `1` error, `2` scope-gap, `3` expired.
- `gcpx doctor` performs a live refresh grant plus token introspection, and
  separately enumerates every credential source visible to the current shell —
  the two environment overrides, `CLOUDSDK_CONFIG`, the well-known ADC file and
  `credentials.db` — reporting which one actually wins for the CLI and which
  for the libraries.
- `gcpx refresh --all --quiet` is the cron target and prints only problems.

## Onboarding

- `gcpx login` wraps the headless browser consent flow: a URL is printed, a
  code is pasted back, no browser needed on the machine running it.
- Minting happens inside a throwaway `CLOUDSDK_CONFIG` directory, so the
  caller's own credential file is never touched. This is what protects against
  the failure mode where a bare `gcloud auth application-default login` — which
  `dbt-bigquery` issues on your behalf — silently strips previously consented
  scopes.
- `gcpx adopt --scan` probes credential files already on the host and reports
  what each one actually is; `gcpx adopt --file` imports one.
- `gcpx rescope <alias> --add drive` re-mints with a wider grant while keeping
  the alias, project and description. Scopes are frozen at consent time, so
  re-minting is the only real mechanism and the command says so.

## Scopes

- Short names (`drive`, `sheets`, `bigquery`) expand to full URLs; presets
  `base`, `dbt`, `sheets` and `full` ship in the box.
- `openid`, `userinfo.email` and `cloud-platform` are force-included in every
  mint. Without the first two, introspection returns no email and the
  credential cannot report which account it belongs to.
- Implied scopes are understood, so a `cloud-platform` credential is not
  falsely reported as missing `bigquery`.
- `drive.file` is explicitly rejected as a substitute for `drive`: it reaches
  only files the OAuth client itself created, so it fails on a pre-existing
  Sheet while still looking present.

## Fleet

- `gcpx export` / `gcpx import` move an identity between hosts, sealed with
  AES-256-GCM under a PBKDF2 passphrase by default. Mint once and distribute:
  Google caps refresh tokens at 100 per account per OAuth client and silently
  invalidates the oldest beyond that.
- `gcpx schedule install` writes a marker-commented crontab entry. crontab
  rather than a systemd user timer, because user units die on logout without
  `loginctl enable-linger`, which needs root.
- `gcpx self-update` swaps the running binary atomically.

## Notes

- Zero external Go dependencies. Linux and macOS, amd64 and arm64.
- The Google Cloud SDK is required only for `login` and `rescope`.
- Background refresh detects death early; it cannot prevent it. It resets the
  six-month inactivity clock and keeps a warm token, but no amount of
  refreshing survives a revocation.
