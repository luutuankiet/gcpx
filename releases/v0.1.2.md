# v0.1.2

## Fleet propagation

Re-consenting on one host silently supersedes the same identity on every other host. The credential file stays intact, the refresh daemon keeps running, and calls just start failing as though the account had been revoked. Nothing on the affected machines can detect it, because from their side nothing changed.

Two new commands close that gap.

```bash
gcpx fleet add box-a box-b     # ssh destinations, recorded once
gcpx push work                 # stream the live credential to each
gcpx push work --to box-a      # or name targets ad hoc
gcpx push work --dry-run       # report targets, send nothing
```

`push` streams an unsealed bundle over ssh stdin: nothing touches disk on either end, and no passphrase lands on a remote command line where a local `ps` could read it. Sealed `export`/`import` remains the right tool for channels gcpx does not control.

## Propagation offered at consent time

`login`, `rescope` and `adopt` now finish by naming the hosts they just invalidated and offering to push. Non-interactive runs print the exact command instead of prompting. This is the only moment the change is visible to anyone, so it is the only sensible place to ask.

## Notes

Sharing one credential across hosts was never the problem and still isn't — any number of machines can refresh the same token concurrently, indefinitely. Only a change to the grant itself needs propagating.
